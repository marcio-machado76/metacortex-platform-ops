# Marketing pessoal

Três teses defendidas com o que este repositório produziu. Cada texto se sustenta
sozinho, e nenhum reaproveita a evidência do outro — a divisão foi deliberada,
para que os três juntos cubram o material sem repetir o golpe.

| # | Texto | Tese | Evidência que sustenta |
|---|---|---|---|
| 1 | [Medi minha automação. Ela não melhorou o resultado.](01-automatizar-e-decidir-o-que-fica-de-fora.md) | O valor de uma automação está tanto no que ela cobre quanto no que ela recusa cobrir | a medição com e sem skill, que deu negativo; o bloco de vocabulário recusado; a varredura medida antes de existir script |
| 2 | [Dei ao agente acesso somente-leitura a todos os clusters.](02-dar-acesso-nao-e-dar-metodo.md) | Ferramenta resolve alcance, não resolve critério | as ferramentas do MCP carregadas um projeto inteiro e nunca usadas; a skill que faltava sendo método de trabalho, não de domínio |
| 3 | [Meu critério de aceite estava errado.](03-o-que-muda-quando-a-especificacao-vem-antes.md) | O que separa entrega boa de descartável é o que existe escrito antes do primeiro prompt | o critério que já nascia falso, com a ordem dos commits provando; os quatro pontos em que a spec não sobreviveu ao contato com o código |

## A ordem não é acidental

O primeiro texto abre admitindo que a automação **não** funcionou como esperado.
Isso não é autossabotagem — é o que compra crédito para os outros dois serem lidos
com menos ceticismo. Começar pela tese mais "eu estava certo" desperdiça o efeito.

## O que todos os três têm em comum

Nenhum afirma nada que não possa ser conferido neste repositório. Cada um fecha
apontando para os arquivos onde a evidência está — saída crua, tabela de medição,
histórico de commits. É a mesma regra que valeu para o resto da entrega: **nada
afirmado sem ser rodado.**
